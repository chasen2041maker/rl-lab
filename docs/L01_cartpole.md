## 倒立摆是什么

一根杆用铰链立在小车上，你只能把小车往左推或往右推，让杆别倒。

| 东西 | 是什么 |
| --- | --- |
| 状态（4 个数） | `obs[0]` 小车位置（米，0 = 轨道正中，超过 ±2.4 就出轨）、`obs[1]` 小车速度、`obs[2]` 杆的角度（弧度，正 = 往右倒，超过 ±12° 也就是 ±0.21 就算倒了）、`obs[3]` 杆的角速度（正 = 正在往右倒） |
| 动作（2 个） | 0 = 往左推，1 = 往右推（每次 10 牛、推 0.02 秒） |
| 奖励 | 每撑住一步 +1 |
| 结束 | 杆倒了、小车出轨（这两种算失败），或者撑满 500 步（10 秒，算时间到） |

## 第 3 步：你来写规则

打开 `rl/policies.py`，把 `rule_policy` 里那行 `raise ...` 换成你的规则：看 `obs` 里的数，返回 0（往左推）或 1（往右推）。

第一版先写最直觉的：**杆往哪边倒，就往哪边推**。写之前先猜：比随机乱推撑得久多少？

写完再跑第 2 步的命令。然后：

1. 开窗口看你的规则是怎么失败的，想一想为什么
2. 换一个数来判断，再跑
3. 两个数一起看，再跑

每一版跑完记下：平均撑几步、结束原因是什么。

## 第 4 步：用你刚跑出来的东西，认识 5 个词

（跑完再看这一步，助手会在聊天里一块一块讲。）

| 词 | 在倒立摆里是什么 |
| --- | --- |
| 环境 environment | 倒立摆这个小世界，`env.step` 让它往前走一步 |
| 状态 state | 那 4 个数 |
| 动作 action | 往左推 / 往右推 |
| 奖励 reward | 每撑一步 +1 |
| 策略 policy | 看到状态、决定动作的那个函数，就是你写的 `rule_policy` |

再加一个：**回报 return** = 一回合所有奖励加起来，倒立摆里就等于撑的步数。强化学习的目标就是找一个让回报最大的策略，而它手里只有奖励，没有任何人告诉它“该看角度还是角速度”。
